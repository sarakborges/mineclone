## Etapa 35 — cache de pacotes e compilação Rust na CI [IMPLEMENTADO, VALIDADO EM RUN FRIO E QUENTE]

**Solicitação expressa do usuário:** não baixar/instalar/recompilar todo Bevy a cada commit. Análise de logs do run anterior https://github.com/sarakborges/mineclone/actions/runs/35223526480: Linux apt cache HIT ~6 MB; `Swatinem/rust-cache@v2` HIT exato ~302 MB, mas o `Cargo.lock` gitignored estava ausente; Cargo re-resolvia 559 pacotes, atualizava crates.io, baixava unicode-ident e recompilava dependências. Clippy 3m35s, check ~8s. Rust 1.98.1 e Clippy já presentes no ubuntu-24.04; ação de toolchain relatou unchanged, não era instalação real demorada.

`7a556186943ef777a4d79fd5872a64a999ec697b`, CI push https://github.com/sarakborges/mineclone/actions/runs/35223779515 `completed/success`: em `.github/workflows/ci.yml`, `actions/cache` para `Cargo.lock` com chave por Cargo.toml e .cargo/config.toml ANTES do rust-cache; gera lock só quando falta, `cargo clippy --locked ... -D warnings` e `cargo check --locked`. Primeiro run naturalmente MISS, gerou lock com 559 pacotes e salvou cache do lock; rust-cache salvou artefatos correspondentes. `Cargo.lock` continua ignorado no git conforme decisão existente.

`d5772dcc90b48eacd850a7b5a110c7ba6cae75db`, CI PR https://github.com/sarakborges/mineclone/actions/runs/35224192069 `completed/success`: atualiza checkout/cache v4 -> v5 (Node 24, eliminando avisos de Node20 dessas actions) e acrescenta etapa de evidência `Report dependency cache`. **Segundo run confirmou HIT EXATO em Cargo.lock (`Cargo.lock restored from cache: true`, hash SHA256 `49799663e1d381a9765ae42373cae8aefa97568f0eb5170c4ea8b1604527ece6`); `Resolve dependencies on cache miss` SKIPPED; rust-cache HIT EXATO chave `v0-rust-validate-Linux-x64-6ff13d87-462d3a21`, ~412 MB restaurados, `full match: true`; Clippy 15.56s, check 7.39s.** Sem `Locking 559 packages`, nenhum novo download de crates nem recompilação massiva do Bevy; somente o crate `asteria` compilou. Ainda aparece `Updating crates.io index` mesmo com `--locked`; evitar downloads/índice completamente exigiria `--offline` após prefetch garantido, não aplicar às cegas. Considerar futuro reuso de cache em PR/push e retenção/expiração; cache hit não garante desempenho igual quando Cargo.toml/toolchain mudarem.
